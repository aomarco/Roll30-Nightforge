## 4. Architecture

### 4.1 Layer boundaries

| Layer | Responsibility |
|---|---|
| Nightforge views | Render state and dispatch commands |
| Application layer | Coordinate workflows, routing, selections, and persistence |
| Domain layer | Pure game rules, validation, calculations, and geometry |
| Repository layer | LocalStorage, IndexedDB, normalization, recovery, and errors |
| Generated data | Clean-room catalogs derived from SRD reference files |

### 4.2 View rules

Views may:

- Display supplied records.
- Track transient presentation state.
- Dispatch user intent.
- Render loading, disabled, error, success, and empty states.

Views may not:

- Calculate AC.
- Calculate attack legality.
- Normalize inventory.
- Apply equipment rules.
- Advance initiative directly.
- Calculate movement.
- Perform pathfinding.
- Interpret conditions.
- Write directly to browser storage.
- Duplicate domain calculations for display.

### 4.3 Application state

Use React context plus reducers. Do not add a global state-library dependency.

Long-lived application state:

```text
scenes
heroes
activeSceneId
route
persistenceStatus
globalError
```

Per-Table state:

```text
selectedTokenId
selectedChestId
camera
activeTool
pointerInteraction
commandDrawer
attackDraft
swapDraft
rulerDraft
wallDraft
cinematic
message
```

Transient state is not persisted unless it represents actual game state.

### 4.4 Command result interface

Every mutating application command returns:

```text
Success:
{ ok: true, value, revision }

Failure:
{
  ok: false,
  code,
  message,
  recovery,
  retryable
}
```

Errors must explain:

- What failed.
- Why, when known.
- Whether user input was preserved.
- What the user can do next.

### 4.5 Randomness

All dice and initiative functions accept an injected random source.

Production uses cryptographically suitable browser randomness or `Math.random` where appropriate.

Tests use deterministic sequences.

## 5. Data contracts

### 5.1 Application envelope

```text
schemaVersion: 1
revision
savedAt
scenes[]
heroes[]
lastActiveSceneId | null
pendingArtworkDeletes[]
checksum
```

Rules:

- State is saved as one validated LocalStorage envelope.
- The previous valid envelope is retained as a backup.
- Each successful save increments `revision`.
- Startup selects the newest valid envelope.
- If the primary envelope is corrupt, load the backup and report recovery.
- If both are invalid, start empty and preserve the corrupt strings for manual diagnosis rather than overwriting them immediately.

## 6. Persistence and artwork recovery

### 6.1 Normal state saves

1. Validate the proposed application envelope.
2. Serialize it.
3. Write the current valid primary envelope to the backup key.
4. Write the new envelope to the primary key.
5. Read and validate the new primary value.
6. Report `Saved` only after verification succeeds.
7. Retain the user’s draft and show `Not saved` if writing fails.

### 6.2 Autosave honesty

Text fields and range controls may update local drafts immediately, but the interface must distinguish:

- Editing.
- Saving.
- Saved.
- Not saved.

A failed save does not erase the draft. Retry uses the preserved draft.

### 6.3 Artwork upload and replacement

LocalStorage and IndexedDB cannot form one atomic transaction. Use staged asset keys:

1. Validate and decode the new image.
2. Generate a new unique `artworkKey`.
3. Store the blob under the staged key in IndexedDB.
4. Read it back to confirm success.
5. Update the Scene envelope to reference the new key.
6. Only after the Scene save succeeds, schedule deletion of the previous artwork key.
7. If Scene saving fails, retain the old reference and delete the staged orphan.
8. If old-artwork deletion fails, add its key to `pendingArtworkDeletes`.
9. Retry pending deletions during later successful startups.

### 6.4 Artwork removal

1. Save the Scene with `artworkKey: null` and the selected blank-canvas state.
2. Add the prior key to `pendingArtworkDeletes`.
3. Delete the artwork from IndexedDB.
4. Remove the pending entry after confirmed deletion.
5. Failure leaves the Scene correctly blank while cleanup retries later.

### 6.5 Scene deletion

1. Remove the Scene from the application envelope.
2. Add its artwork key to `pendingArtworkDeletes`.
3. Save and verify the envelope.
4. Delete artwork afterward.
5. Failed artwork cleanup cannot resurrect the Scene.
6. Cleanup is retried at startup.
7. If removing the Scene envelope fails, the UI continues showing the Scene and reports failure.

### 6.6 Corrupt or incompatible Nightforge encounters

- Invalid encounter data reopens the Battle scene in Setup.
- Scene, token, chest, and wall data remain available.
- Original Roll30 encounter versions are never recognized or imported.
- An explicitly empty hand remains empty.
- No normalizer silently equips a weapon except during creation of a new blank default when the product rules explicitly require it.

### 9.3 Walls and pathfinding

- Full and half walls are persisted percentage polylines.
- Escape finishes the current wall run.
- Hidden walls still function.
- Both wall types block movement.
- Full walls block ranged and thrown line of sight.
- Half-walls impose disadvantage.
- Melee ignores wall line of sight.
- New clean-room 8-directional A* routes around walls and occupied cells.

- Four-connected grid traversal.

- Exclude origin.
- Multiply by 5 feet.
- Render line and midpoint label in world space.

### 9.5 Initiative

Starting requires two or more tokens.

- Roll d20 plus initiative bonus.
- Sort descending.
- Ties retain pre-roll token-list order for deterministic stability.
- Round starts at 1.
- First token becomes active.
- First token receives fresh resources.
- Conditions are cleared at new Battle start.
- Old physical battle items are cleared.

### 9.6 Movement

- One cell costs 5 feet.
- Movement is splittable.
- Movement may happen before and after Attack.
- Token stays at origin during preview.
- Start cell is white.
- Reachable route is green.
- Over-budget route is red.
- Dropping beyond allowance stops at farthest reachable green cell.
- Occupied final cell steps backward along the route.
- Invalid route leaves token at origin.
- Wall detours charge complete routed distance.
- Immobilized tokens have no movement.
- Valid movement uses Nightforge arrival motion.

### 9.7 Dash

- Spends Action.
- Adds one complete Speed value to maximum movement.
- Preserves already spent movement.
- Does not move automatically.
- Leaves Bonus Action available.
- Prevents Attack and Swap.
- Unavailable after Attack, Swap, or prior Dash.

### 9.8 Attack Action

- Spends Action.
- Does not spend movement.
- Does not end turn.
- Prevents Dash.
- Prevents later Swap.
- May unlock off-hand Bonus Action.
- Remaining movement remains usable.

### 9.9 Swap

Once per turn.

Unavailable after:

- Attack.
- Dash.
- Prior Swap.

Branches:

- Swap then Attack: disadvantage, no movement, no Dash.
- Swap then Move: no Attack, no Dash, remaining movement usable.
- Move then Swap: no Attack, no Dash.
- Turn still ends manually.

### 9.10 End Turn

- Only normal initiative-advance path.
- Skip defeated tokens.
- Increment round on wrap.
- Create fresh resources from the next token’s Speed.
- Discard unused movement.
- Close transient command states.
- Do not auto-advance after attacks, movement, Dash, Swap, retrieval, or looting.

### 9.11 Dual wielding

Requires:

- Two equipped melee weapons.
- Both Light.
- Neither Two-Handed.

After main Attack:

- Other weapon becomes off-hand attack weapon.
- Bonus becomes available.
- Positive ability modifier omitted from off-hand damage.
- Negative modifier retained.
- Attack and proficiency modifiers still apply.
- Swap attack does not unlock off-hand.
- Bonus attack does not end turn.

### 9.12 Attack calculation

```text
d20 + ability modifier + proficiency bonus + magic attack bonus
```

Ability:

- Melee: Strength.
- Ranged: Dexterity.
- Finesse: better of Strength or Dexterity.
- Thrown melee: normal melee ability.
- Finesse thrown: better ability.

Rules:

- Natural 1 always misses.
- Natural 20 always hits.
- Natural 20 doubles dice only.
- Total meeting AC hits.
- Ability modifier added once to damage.
- Fixed damage supported.
- Final damage cannot be negative.

### 9.13 Advantage and disadvantage

- Normal: one d20.
- Advantage: two, keep high.
- Disadvantage: two, keep low.
- Opposing sources cancel.
- Multiple sources do not create more dice.
- Damage remains normal.

Sources include:

- Long range.
- Long throw.
- Heavy weapon used by Small creature.
- Lance used at 5 feet.
- Attack after Swap.
- Half-wall shot.
- Attacker conditions.
- Target conditions.

### 9.14 Range display

Use one SVG rather than per-cell React nodes.

- Stair-stepped polygon per range tier.
- Grid pattern clipped to valid cells.
- Aligned to actual board grid.
- Centered on attacker cell.

Colors:

| Attack | Tier |
|---|---|
| Melee | Green |
| Reach | Green to 10 ft |
| Ranged normal | Green |
| Ranged long | Yellow |
| Thrown melee | Green |
| Thrown normal | Yellow |
| Thrown long | Red |

Full-wall and out-of-range targets cannot be selected and do not spend Action.

### 9.15 Conditions

Implement all 15:

- Blinded.
- Charmed.
- Deafened.
- Frightened.
- Grappled.
- Incapacitated.
- Invisible.
- Paralyzed.
- Petrified.
- Poisoned.
- Prone.
- Restrained.
- Stunned.
- Unconscious.
- Exhaustion.

Effects:

- Attacker roll bias.
- Target melee/ranged roll bias.
- Incapacitation.
- Immobilization.
- Automatic melee critical against Paralyzed or Unconscious targets.
- Normal advantage/disadvantage cancellation.
- Manual Nightforge toggles.
- Nightforge token badges.
- No automatic application.

### 9.16 Chests

Setup:

- Add.
- Drag.
- Block occupied cell.
- Fill using complete catalog.
- Change quantities.
- Delete.

Battle:

- Eligible when adjacent and Bonus Action available.
- Opening spends Bonus Action.
- Take one unit at a time.
- Contents deplete.
- Empty state persists.
- Chest blocks movement.
- Restart does not refill.

### 9.17 Thrown weapons

Lodging:

- Dagger.
- Dart.
- Handaxe.
- Javelin.
- Spear.
- Trident.

Non-lodging:

- Light Hammer.

Behavior:

- Infer throw from target distance.
- Remove one inventory copy.
- Clear thrown hand.
- Shift remaining off-hand weapon into main hand when necessary.
- Lodging hit embeds.
- Non-lodging hit lands nearby.
- Miss lands nearby.
- Landing avoids occupied and invalid cells.
- Physical items persist only in versioned active encounters.

### 9.18 Retrieval

Embedded living target:

- Carrier or adjacent actor.
- Bonus Action.
- `d20 + STR modifier + DEX modifier`.
- DC 15.
- Failure spends Bonus and leaves item embedded.

Ground:

- Same or adjacent square.
- Bonus Action.
- No roll.

Defeated carrier:

- Adjacent.
- Free.
- No roll.

Recovery:

- Equip into legal empty hand without Swap penalty.
- Otherwise add to inventory.
- Stored weapon requires later Swap.

### 9.19 Ammunition

- Arrow bundle 20.
- Bolt bundle 20.
- Sling Bullet bundle 20.
- Blowgun Needle bundle 50.
- Matching ammunition required.
- One unit consumed per shot.
- Expenditure tracked per token.
- On completion, recover floor of 50% fired.
- Completion recovery occurs once.

### 9.20 Cinematics

Attack:

1. Spin one or two d20s.
2. Reveal natural roll.
3. Reveal modifiers.
4. Compare with AC.
5. Show hit, miss, or critical.
6. Roll damage when hit.
7. Display damage modifier.
8. Apply HP.
9. Display floating damage and token impact.

Retrieval:

1. Spin d20.
2. Show STR and DEX contributions.
3. Compare with DC 15.
4. Show success or failure.
5. Update item only after result.

Rules:

- Rejected die is visibly de-emphasized.
- Successful hits use a newly authored Nightforge-compatible impact sound.
- Misses do not play hit sound.
- Input locks during resolution.
- Reduced motion shortens or replaces animation without removing information.

### 9.21 Completion and restart

Complete when one or zero living tokens remain.

- Report winner or no survivor.
- Disable ordinary combat.
- Recover ammunition once.
- Preserve final encounter for reload.

Restart:

- Restore all tokens to Max HP.
- Roll new initiative.
- Reset rounds and resources.
- Clear conditions and physical battle items.
- Preserve positions, Scene tools, walls, and depleted chests.
- Begin a fresh active encounter.
