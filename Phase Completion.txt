3. APPLICATION FOUNDATION IMPLEMENTED
-------------------------------------

Created a new application layer with:

- A stable success result shape:
  { ok: true, value, ...metadata }
- A stable failure result shape:
  { ok: false, code, message, recovery, retryable, cause? }
- An initial application state that always starts at Library.
- A reducer for hydration, navigation, active Scene context, Scene/Hero lists,
  and explicit persistence status.
- Persistence states: idle, saving, saved, and error.
- Application commands for initialization, navigation, Scene selection, Scene
  CRUD, and Hero CRUD.
- Route validation that prevents Scene Settings or Table from opening without
  a selected Scene.
- Durable active-Scene selection with session context as a secondary convenience.
- Stale session cleanup when an active Scene is deleted.
- Preservation of active Scene context without allowing a reload to bypass
  Library.

Files:

- src/application/result.js
- src/application/state.js
- src/application/commands.js

7. PRIMARY/BACKUP STATE REPOSITORY IMPLEMENTED
----------------------------------------------

Implemented behavior:

- Reads primary and backup state independently.
- Chooses the newest valid revision.
- Starts empty without writing when no save exists.
- Recovers from a corrupt primary using the valid backup.
- Preserves the previous valid primary before a new save.
- Increments revision on every successful save.
- Reads the just-written state back and validates it before reporting success.
- Attempts to restore the prior primary if verification fails.
- Converts read, write, and verification failures into actionable result objects.
- Keeps failed edits available to the future application layer rather than
  falsely reporting them as saved.

File:

- src/storage/stateRepository.js
